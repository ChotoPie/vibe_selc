# 프로젝트 요구사항 정의서 (PRD) - 마이링크(My-Link)

## 1. 프로젝트 개요
- **프로젝트명**: 마이링크 (My-Link)
- **목적**: 인스타그램, 틱톡, 깃허브 등 단 하나의 링크만 허용되는 소셜 미디어 프로필에 여러 개의 링크와 포트폴리오를 제공할 수 있도록 돕는 '멀티 링크 랜딩 페이지' 서비스.
- **대상 사용자**:
  - **개발자**: 깃허브, 기술 블로그, 이력서, 포트폴리오 등을 한곳에 모아 공유하려는 개발자
  - **크리에이터**: 유튜브, 인스타그램, 틱톡 등 다양한 채널을 운영하는 인플루언서 및 콘텐츠 크리에이터

## 2. 핵심 기능 목록

1. **회원 인증 및 계정 관리 (Firebase 구글 로그인)**
2. **프로필 관리 (이미지 없음, displayName(URL)/username(실제이름) 분리, 인라인 편집)**
3. **링크 관리 (CRUD, 인라인 편집, 구글 API 파비콘)**
4. **퍼블릭 프로필 페이지 (displayName 기반 URL)**
5. **UI (shadcn/ui 적용)**

*참고: 개별 링크의 클릭 조회수 통계 기능은 추후 추가 기능으로 구현 예정.*

## 3. 각 기능의 상세 설명

### 3.1. 회원 인증 및 계정 관리
- **구글 소셜 로그인 (Firebase)**: 이메일 가입 없이 Firebase Auth를 이용한 구글 로그인만 지원하여 빠르고 간편한 가입 유도.
- **URL 슬러그(`displayName`) 자동 설정**: 최초 구글 로그인 성공 시, 사용자의 구글 지메일 아이디(이메일의 `@` 앞부분)를 추출하여 퍼블릭 페이지 URL(예: `mylink.com/지메일아이디`)로 사용될 `displayName`의 초기값으로 자동 설정. 핸들(`@`) 기호 없이 `displayName` 자체를 URL 경로로 사용.
- **계정 관리**: 구글 연동 해제 및 회원 탈퇴 기능.

### 3.2. 프로필 관리
- **이미지 업로드 없음**: 프로필 이미지 기능은 제공하지 않음.
- **식별자(URL)와 표시 이름의 분리**: 고유한 URL 경로(슬러그)로 사용되는 **`displayName`**과, 프로필 화면 상단에 실제 사용자 이름(또는 직군/타이틀)으로 예쁘게 노출될 **`username`**을 명확히 분리하여 운영.
- **인라인 편집 (Inline Edit)**: 프로필 화면에 노출되는 실제 사용자 이름(`username`)과 소개글(Bio) 등은 별도의 폼 페이지 이동 없이, 화면에서 직접 클릭하여 즉시 수정(인라인 편집)할 수 있도록 구현.
- **수정 가능 항목**: URL 슬러그(`displayName`), 사용자 이름(`username`), 소개글(Bio).

### 3.3. 링크 관리
- **링크 추가**: 타이틀과 URL을 입력하여 새로운 버튼형 링크 생성.
- **인라인 편집 (Inline Edit)**: 기존에 등록된 링크의 정보(타이틀, URL)를 수정할 때 인라인 편집 방식을 사용하여 직관적인 수정 환경 제공.
- **구글 파비콘 API**: 등록된 링크의 대상 URL에서 파비콘을 추출할 때 **Google Favicon API**(`https://www.google.com/s2/favicons?domain=...`)를 사용하여 해당 링크 버튼의 아이콘으로 노출.
- **링크 삭제**: 등록된 링크 삭제 기능.

### 3.4. 퍼블릭 프로필 페이지
- **고유 URL 제공**: 사용자가 설정한 `displayName`을 기반으로 접속 가능한 웹 페이지 생성 (`/displayName`).
- **반응형 웹 디자인**: 모바일 기기 우선의 최적화된 UI 및 데스크탑 환경 지원.

### 3.5. UI (shadcn/ui)
- **디자인 시스템 적용**: `shadcn/ui`를 활용하여 모던하고 깔끔한(Minimalist) 디자인 제공. 별도의 테마 변경 기능은 제공하지 않음.

## 4. 데이터베이스 모델링 가이드 (Firebase Firestore)
- 사용자 정보를 저장하는 기본 User 문서(Document)에 URL 슬러그로 사용될 `displayName` 필드와, 화면에 노출될 실제 이름인 `username` 필드를 모두 필수적으로 포함.
- 사용자가 생성한 여러 개의 링크 데이터는 단일 배열이 아닌, 해당 User 문서 하위의 **서브 컬렉션(Sub-collection)**으로 저장하고 관리.
